1. Protokole Genel Bakış

MultiUserPaint Uygulama Protokolü (kısaca MAP), birden fazla kullanıcının aynı anda ortak bir çizim tuvali üzerinde çalışmasına olanak tanıyan, istemci-sunucu mimarisine dayalı bir uygulama katmanı protokolüdür.

1.1 Tasarım Kararları

KonuKararGerekçe
Transport katmanıTCPÇizim verisi sıralı ve kayıpsız iletilmelidir. Piksel kaybı görsel bozulmaya neden olur.
Mesaj çerçevelemeBinary, sabit başlık + değişken payloadJSON/metin tabanlı protokoller büyük piksel verisi için verimsizdir. Binary kodlama hem kompakt hem de hızlıdır.
Byte sırasıBig-endian (network byte order)Ağ standartlarıyla uyumluluk; platform bağımsızlığı.
Sunucu mimarisiNon-blocking I/O (Selector)Tek thread ile çok sayıda istemciyi yönetmek için bloklanmayan G/Ç gereklidir.
Kimlik doğrulamaKullanıcı adı tabanlıProje kapsamı dahilinde basit ve işlevsel.

1.2 Mimari

Sistemde bir sunucu ve birden fazla istemci bulunur. İstemciler birbirleriyle doğrudan iletişim kurmaz; tüm mesajlar sunucu üzerinden iletilir (merkezi model). Sunucu durum bilgisini saklar: bağlı kullanıcılar, paylaşılan dosyalar ve her kullanıcının pano verisi sunucuda tutulur.

2. Wire Frame Formatı

Her MAP mesajı aşağıdaki sabit başlık ile başlar ve ardından değişken uzunluklu payload gelir. Başlık her zaman 8 bayttır.

0 1 2 3 4 5 6 7 ┌────────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┐ │ 0xCA │ 0xFE │ VER │ TYPE │ PAY_LEN (4 bayt, big-endian) │ └────────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┘ │◄── MAGIC (2 B) ──►│ (1B) │ (1B) │◄─────────── 4 bayt ─────────────►│ Devamında: ┌─────────────────────────────────────────────────────────────────────────┐ │ PAYLOAD (PAY_LEN bayt) │ └─────────────────────────────────────────────────────────────────────────┘
AlanBoyutDeğer / Açıklama
MAGIC2 baytSabit: 0xCAFE. Geçersiz MAGIC bağlantının anında kapatılmasına neden olur.
VERSION1 baytProtokol versiyonu. Mevcut sürüm: 0x01. Gelecek sürümlerle geriye dönük uyumluluk için ayrılmıştır.
TYPE1 baytMesaj tipi kodu (Bölüm 3'e bakınız).
PAY_LEN4 baytPayload uzunluğu (bayt). Big-endian işaretli tam sayı. Maksimum 1.048.576 (1 MB). Aşan mesajlar reddedilir.
PAYLOADPAY_LEN baytMesaja özgü veri. TYPE = 0 ise payload boştur (PAY_LEN = 0).

2.1 String Kodlama Kuralı

Payload içindeki her metin değeri aşağıdaki şema ile kodlanır. Bu kural tüm payload tanımlarında geçerlidir:

┌──────────┬────────────────────────────────┐ │ UZUNLUK │ UTF-8 BAYTLARI │ │ 2 bayt │ UZUNLUK kadar bayt │ └──────────┴────────────────────────────────┘ Uzunluk: big-endian işaretsiz short (0–65535)

4. Mesaj Payload Şemaları

Tüm çok baytlı sayılar big-endian kodlamasını kullanır. Metin alanlarında Bölüm 2.1'deki String kodlama kuralı uygulanır.

LOGIN_REQ (0x01)

┌──────────────────────────────────────┐ │ kullanici_adi : STRING │ └──────────────────────────────────────┘ Kural: 3–16 karakter, yalnızca [a–z A–Z 0–9 _]

LOGIN_OK (0x02)

┌────────────────────┬────────────────────────────────────┐ │ oturum_id │ sunucu_saati │ │ 4 bayt (int) │ 8 bayt (long, Unix epoch ms) │ └────────────────────┴────────────────────────────────────┘

LOGIN_ERR (0x03)

┌────────────┬──────────────────────────────────────────┐ │ hata_kodu │ hata_mesaji : STRING │ │ 1 bayt │ │ └────────────┴──────────────────────────────────────────┘ Hata kodları: 0x01 = Kullanıcı adı alınmış 0x02 = Geçersiz karakterler 0x03 = Sunucu kapasitesi dolu

FILE_CREATE_REQ (0x10)

┌──────────────────────┬────────────────────┬────────────────────┐ │ dosya_adi : STRING │ genislik (int) │ yukseklik (int) │ │ │ 4 bayt │ 4 bayt │ └──────────────────────┴────────────────────┴────────────────────┘

FILE_CREATE_OK (0x11)

┌────────────────────┬──────────────────────────┐ │ dosya_id (int) │ dosya_adi : STRING │ │ 4 bayt │ │ └────────────────────┴──────────────────────────┘

FILE_OPEN_REQ (0x12)

┌──────────────────────────────────────────────────┐ │ hata_mesaji : STRING │ └──────────────────────────────────────────────────┘

PING (0xF0), PONG (0xF1), FILE_SAVE_OK (0x17), FILE_DELETE_OK (0x19), CLIPBOARD_PASTE_REQ (0x31), USER_LIST_REQ (0x42), FILE_LIST_REQ (0x14), FILE_OPEN_REQ (0x12)

Bu mesajlar için ya payload boştur (PAY_LEN = 0) ya da yalnızca dosya_id içerir (4 bayt int).

5. Sunucu Sonlu Durum Makinası (FSM)

Sunucu, her TCP bağlantısı için bağımsız bir FSM örneği çalıştırır. Bir istemcinin durumu yalnızca o istemciye ait mesajlar tarafından değiştirilir.

5.1 Durum Diyagramı

8.3 Canlılık Mekanizması (Keepalive)

İstemci her 30 saniyede bir PING gönderir. Sunucu PONG ile yanıt verir ve son PING zamanını günceller. Sunucu, herhangi bir oturumdan 90 saniye boyunca PING gelmediğini tespit ederse o oturumu zaman aşımına uğramış kabul ederek bağlantıyı kapatır.
