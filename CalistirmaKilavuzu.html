MultiUserPaint — Çalıştırma ve Test Kılavuzu

Bu kılavuz, projeyi sıfırdan derleyip çalıştırmak ve her iki transport modunu (Socket ve RabbitMQ) test etmek için gerekli tüm adımları içerir.

!

NetBeans ile Derle

IDE içinde derleme ve doğrudan çalıştırma
  1. NetBeans'i açın → File → Open Project → MultiUserPaint klasörünü seçin.
  2. Sol panelde projeye sağ tıklayın → Clean and Build.
  3. Sunucuyu çalıştırmak için: Run → Set Project Configuration → server, ardından Run Project.
  4. İstemciyi çalıştırmak için: Konfigürasyonu client'a çevirin, tekrar Run.
NetBeans nbproject/project.properties dosyasını kullanır. Kaynak uyumluluk zaten 1.8 (Java 8) olarak ayarlıdır.

BÖLÜM 4 — RabbitMQ Modunda Çalıştırma RabbitMQ

5

RabbitMQ Kurulumu Windows

Broker yoksa bu adımı uygulayın

Seçenek A — Chocolatey ile (Önerilen)

# PowerShell — Yönetici olarak çalıştır
choco install rabbitmq -y

Seçenek B — Manuel Kurulum

  1. Erlang/OTP indirin: https://www.erlang.org/downloads → Windows installer.
  2. RabbitMQ indirin: https://www.rabbitmq.com/install-windows.html → Windows installer.
  3. Sırasıyla kurun: önce Erlang, sonra RabbitMQ.

Seçenek C — Docker ile (En Hızlı)

# Docker Desktop kuruluysa:
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management

-p 5672:5672 AMQP portu, -p 15672:15672 yönetim paneli portudur.

RabbitMQ Servisini Başlat (Manuel kurulumda)

# PowerShell — Yönetici olarak
Start-Service RabbitMQ

# Veya komut satırından:
rabbitmq-server start
Erlang kurulum sırası önemlidir: RabbitMQ kurulmadan önce Erlang kurulmalıdır. Aksi hâlde RabbitMQ servisi başlamaz.

İstemciyi MQ Modunda Başlat

Login ekranında "MQ" modunu seçin

Komut (socket ile aynı)

java -jar dist\MultiUserPaint.jar

Login Ekranında Doldurulacak Alanlar

AlanDeğer (MQ Modu)
ModeMQ (radyo butonu)
Broker Hostlocalhost (aynı makinede) veya broker IP adresi
Username3-16 karakter, harf/rakam/alt çizgi

MQ Modunda İstemci Başlangıç Akışı

  1. İstemci paint.client.<UUID> adlı özel kuyruk oluşturur.
  2. paint.global fanout exchange'e bağlanır (USER_JOIN/LEAVE alır).
  3. Login_REQ mesajını paint.server kuyruğuna gönderir (AMQP header'larıyla).
  4. Sunucu LOGIN_OK'u doğrudan kişisel kuyruğa (replyTo) gönderir.
  5. Dosya açınca paint.file.{fileId} exchange'e bağlanır.
Çoklu istemci: Her istemci benzersiz UUID ile kendi kuyruğunu oluşturur. Aynı anda aynı makinede istediğiniz kadar istemci açabilirsiniz — kuyruk isimleri çakışmaz.

Çizim Senkronizasyonu Testi

Bir istemcide çizilen şekil diğerlerinde anlık görünmeli
  1. 2 veya daha fazla istemci aynı dosyayı açsın.
  2. İstemci A'da araç çubuğundan Kalem seçin, canvas'a çizin.
  3. Beklenen: İstemci B'de çizgi anında görünür, üstünde A'nın kullanıcı adı gösterilir.
  4. İstemci B'de Dikdörtgen aracıyla şekil çizin.
  5. Beklenen: İstemci A'da dikdörtgen görünür.
  6. 3. bir istemci C aynı dosyayı açsın.
  7. Beklenen: C, A ve B'nin tüm çizimlerini (canlı canvas) görür — diskten değil, A veya B'den senkronize alır.

Sunucu Logunda Görünmesi Beklenenler

# Socket modunda:
DRAW_EVENT → broadcastToFileViewers(fileId=1, exclude=sessionId)

# MQ modunda — per-file exchange:
BİLGİ: Bound to file exchange: paint.file.1  (istemci C açtığında)
Canvas senkronizasyonu (3. istemci): C dosyayı açınca sunucu, A veya B'den CANVAS_SNAPSHOT_REQ ile anlık canvas ister. A veya B cevap olarak CANVAS_SNAPSHOT_DATA gönderir. Sunucu bunu C'ye FILE_OPEN_DATA olarak iletir. Bu sayede C boş canvas yerine güncel durumu görür.

T4

Pano (Kopyala / Kes / Yapıştır) Testi

Pano verisi sunucuda oturuma özgü saklanır
  1. İstemci A ve B aynı dosyayı açsın.
  2. İstemci A'da Seçim aracını seç, canvas'ta bir alan seç.
  3. Kopyala: Ctrl+C veya araç çubuğu kopyala butonu.
  4. Yapıştır: Ctrl+V veya araç çubuğu yapıştır butonu, hedef koordinata tıkla.
  5. Beklenen: Kopyalanan bölge hem A'ya hem B'ye (ve dosyayı açık olan tüm istemcilere) gönderilir.
  6. Aynı işlemi Kes (Ctrl+X) ile tekrarlayın.
  7. Beklenen: Kesilen bölge A'nın canvas'ından silinir; yapıştırma yine çalışır.
Pano izolasyonu: A'nın panosu B'yi etkilemez. B kendi Ctrl+C'sini yapana kadar A'nın kopyaladığını yapıştıramaz.
T5

Undo Senkronizasyonu Testi

Geri alma işlemi diğer kullanıcılara yayılır
  1. İstemci A ve B aynı dosyayı açsın.
  2. İstemci A'da birkaç çizgi çizin.
  3. İstemci A'da Z tuşuna basın (Undo).
  4. Beklenen A: Son çizgi geri alınır.
  5. Beklenen B: B'nin canvas'ı da A ile senkronize olur — A'nın undo sonrası durumunu gösterir.

Undo Mekanizması

# İstemci A, Z tuşuna basınca:
1. canvas.undo()                          → yerel stack'ten geri al
2. connection.sendCanvasSnapshotData(...)  → sunucuya güncel canvas gönder

# Sunucu CANVAS_SNAPSHOT_DATA alınca:
3. pendingOpens listesini işle            → bekleyen yeni istemciler varsa onlara gönder
4. broadcastToFileViewers(CANVAS_UPDATE)  → B ve diğerlerine yay

# İstemci B CANVAS_UPDATE alınca:
5. canvas.fromPixelBytes(...)             → canvas A ile senkronize
Undo stack maksimum 20 adım tutar. 20'den fazla geri alma yapılamaz.
T6

Keepalive / Bağlantı Kopma Testi

90 saniye işlem yapmayan oturum kapanır
SenaryoAdımlarBeklenen Sonuç
Normal keepalive İstemci açık, 30+ saniye bekle Logda PING/PONG; bağlantı kesilmez
Kullanıcı pencereyi kapatır İstemci X penceresini kapat Diğer istemcilere USER_LEAVE yayını; kullanıcı listesinden düşer
Zaman aşımı simülasyonu İstemci sürecini kill et (taskkill /F /PID <pid>); 90 saniye bekle Sunucu 90 saniye PING gelmeyince oturumu kapatır ve USER_LEAVE yayar

Sunucu Logunda Zaman Aşımı

UYARI: Keepalive timeout for ali
BİLGİ: User disconnected (MQ timeout): ali
Değerleri değiştirmek için: ProtocolConstants.java içindeki PING_INTERVAL_SECONDS (30) ve KEEPALIVE_TIMEOUT_SECONDS (90) sabitlerini düzenleyip yeniden derleyin.

BÖLÜM 6 — Sorun Giderme

⚠

Port Meşgul / Bağlantı Reddedildi

Hata Mesajı

java.net.BindException: Address already in use: NET_Bind

Çözüm — Portu Kullanan Süreci Bul ve Durdur

# Portu kim kullanıyor?
netstat -ano | findstr :9090

  TCP    0.0.0.0:9090    0.0.0.0:0    LISTENING    12345

# Süreci sonlandır (12345 yerine kendi PID'inizi yazın)
taskkill /F /PID 12345

Veya Farklı Port Kullan

java -jar dist\MultiUserPaintServer.jar 9091
# İstemcide de port alanını 9091 yap
⚠

RabbitMQ Bağlantı Hatası

Hata Mesajları

com.rabbitmq.client.AlreadyClosedException: clean connection shutdown
java.net.ConnectException: Connection refused: localhost/127.0.0.1:5672

Kontrol Listesi

  • RabbitMQ servisi çalışıyor mu? → rabbitmqctl status
  • Port 5672 açık mı? → Test-NetConnection localhost 5672
  • Firewall port 5672'ye izin veriyor mu?
  • Docker kullanıyorsanız container çalışıyor mu? → docker ps
  • Sunucu --mq flag'i ile başlatıldı mı?
  • İstemcide doğru broker host girildi mi?

RabbitMQ Servisini Yeniden Başlat

# PowerShell — Yönetici olarak:
Restart-Service RabbitMQ

# Docker kullanıyorsanız:
docker restart rabbitmq

RabbitMQ Yönetim Panelini Etkinleştir (Opsiyonel)

rabbitmq-plugins enable rabbitmq_management
# Tarayıcıda: http://localhost:15672  (guest/guest)
⚠

Derleme Hataları

Hata: javac bulunamadı

The term 'javac' is not recognized...

Çözüm: JDK'nın bin dizinini PATH'e ekleyin veya build.ps1 içindeki $jdk21 değişkenini kendi JDK yolunuza güncelleyin.

# build.ps1 içinde:
$jdk21 = "C:\Program Files\Java\jdk-21\bin"
# Bu satırı kendi JDK kurulum yolunuza göre değiştirin

Hata: lib/ klasörü eksik

error: package com.rabbitmq.client does not exist

Çözüm: lib/ klasörünün şu dosyaları içerdiğini kontrol edin:

Get-ChildItem .\lib\

amqp-client-5.21.0.jar
slf4j-api-1.7.36.jar
slf4j-simple-1.7.36.jar

Hata: execution policy

.\build.ps1 : File ... cannot be loaded because running scripts is disabled on this system.

# Geçici çözüm:
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\build.ps1

Hata: Türkçe karakter sorunu (UTF-8)

error: unmappable character (0xC4) for encoding windows-1252

Çözüm: Derleme komutu zaten -encoding UTF-8 içeriyor. Ant ile derliyorsanız build.xml'de encoding="UTF-8" var — sorun devam ederse:

# Ant'a JVM parametresi verin:
ant -Dfile.encoding=UTF-8 jar
